# OpenShift Airgap Architect v2.1.1

**Version:** 2.1.1 (PATCH) · **Supported OpenShift targets:** 4.20, 4.21, 4.22 (unchanged) ·
**Published assets, if any:** the [Releases page](https://github.com/bstrauss84/openshift-airgap-architect/releases)

v2.1.1 is a small corrective release on top of [v2.1.0](v2.1.0.md). It changes no
OpenShift support, no generated-configuration semantics and no deployment model. It is
delivered the same way: source plus a Docker/Podman Compose deployment, built locally
with the ordinary commands:

```bash
podman compose up --build -d
# or
docker compose up --build -d
```

No Git revision has to be supplied for any feature, including update checks.

## Upgrade note — read this first

**Existing v2.1.0 installations may not tell you that v2.1.1 exists.** The update check
shipped in v2.1.0 was incomplete. It could never raise the "update available" banner, and
with the default Compose build it reported that the build "cannot be identified". Only
installations running v2.1.1 or later benefit from the repaired check. If you are on
v2.1.0, update manually using [`docs/UPDATING.md`](../UPDATING.md), and save your
configuration with **Tools → Export Run** first.

## Fixed

### Update notifications work again

- The backend now compares the **installed application version** (from `package.json`)
  with the newest **published GitHub Release** of the configured repository (`APP_REPO`).
- A release counts only if:
  - it is published, not a draft;
  - it is not a prerelease;
  - its tag is a stable `MAJOR.MINOR.PATCH`;
  - its release metadata names the configured repository;
  - it is **strictly newer** than what is installed.
- **No downgrade prompts.** An older or equal release is never offered.
- **Neither the Git revision nor a branch head is consulted.** A different commit is not
  an update, and an unknown revision no longer disables the check.
- **Failures stay truthful.** If GitHub cannot be reached, times out, rate-limits the
  request, returns malformed data, or returns data for a different repository, the app
  says the check is unavailable. It never says "up to date".
- `CHECK_UPDATES=false` still disables the check without any network request.
- **Trust boundary:** this trusts GitHub's published-release API state over HTTPS. It
  does not verify release signatures or checksums.
- **Wording:** the banner names the published version and the installed version, and
  links the release notes and the update guide. It keeps the Export/Import Run guidance.
- **Tools → About keeps its update status inside the wizard.** Previously the status was
  fetched only on the landing page, and it disappeared whenever the wizard reloaded its
  version data.
- **A failed status request now reads "unavailable"**, not "disabled".

### Build identity is reported truthfully

- **About and Tools** show the application version and build date.
- **The revision is shown only when it is actually known.** A missing revision no longer
  produces "(dev)", "dev build" or "Build unknown". The application version is
  independent of it.
- **The configured `APP_BRANCH`** (Compose sets it to `main`) is no longer displayed as
  if it were the branch the build came from.
- **The backend startup banner** prints the version, and prints revision and build time
  only when known.
- **Feedback issue drafts** include the app version and label the branch
  "Configured APP_BRANCH".

### Corrected repository address

The stale `billstrauss/` repository URL, which returns 404, was corrected to
`bstrauss84/` everywhere it appeared:
- the header of every generated `install-config.yaml` and `agent-config.yaml`;
- the exported Field Guide footer;
- the console and backend banners;
- the About dialog.

## API changes (`GET /api/update-info`)

- **New field:** `installedVersion`.
- **`releaseIdentity`:** now populated when the lookup completes, with the newest
  eligible release in `releaseIdentity.latest`, or `null` if there is none.
- **`updateStatus` values:** one of `disabled`, `unknown`, `offline`, `up-to-date`,
  `published-supported-update`. The `development-branch-ahead` value is retired.
- **Legacy fields, kept for compatibility:**
  - `latestSha` is always `null`.
  - `isOutdated` now equals `urgent`.
  - `currentSha` is provenance only.

See [docs/API.md](../API.md).

## Testing and certification

- **What was run on this source:** the full frontend and backend suites, the version
  and release-document gates, the tranche security gate, and production builds. Live
  checks against the real GitHub Releases API also ran before release: an installed
  2.1.1 compared against the published v2.1.0 reported up to date (no downgrade prompt),
  and a simulated older install was offered v2.1.0.
- **Certification.** This document deliberately states **no** certification verdict for
  v2.1.1. A verdict is valid only for a run bound to the exact released commit, and is
  published with that release's evidence on the
  [Releases page](https://github.com/bstrauss84/openshift-airgap-architect/releases),
  together with any owner risk acceptance. The v2.1.0 certification evidence, its verdict
  and its owner acceptance are bound to the v2.1.0 commit and **do not carry over** to
  this source. Passing regression suites are not a certification result.
- **v2.1.0 findings still apply.** The v2.1.0 findings — including the failing
  `image-vulnerabilities` axis and the incomplete compatibility and connectivity axes —
  are **not** resolved by this patch, because it changes no base images or dependencies.
  See the [v2.1.0 notes](v2.1.0.md) and
  [SBOM and provenance](../security/SBOM_AND_PROVENANCE.md).

## Known issues

- **AWS GovCloud region dropdown can render too tall** (tracked as DOC-228). At some
  window widths, selecting a region makes the region dropdown about twice its normal
  height, because it stretches to match the neighbouring RHCOS AMI controls when they
  wrap. The layout is cosmetic: the selected value, saved state and generated YAML are
  unaffected. The bug is present in v2.1.0 as well and is planned for a later
  maintenance release.
