# OpenShift Airgap Architect v2.2.2

**Version:** 2.2.2 (PATCH) · **Supported OpenShift targets:** 4.20, 4.21, 4.22 (unchanged) ·
**Published assets, if any:** the [Releases page](https://github.com/bstrauss84/openshift-airgap-architect/releases)

v2.2.2 is an emergency maintenance release on top of [v2.2.1](v2.2.1.md). It fixes a backend image build failure
caused by an upstream change at Red Hat. It changes no OpenShift support, no dependencies or base images, and no
deployment model. Build and run it the usual way:

```bash
podman compose up --build -d
# or
docker compose up --build -d
```

Before updating, save your configuration with **Tools → Export Run**. Follow [`docs/UPDATING.md`](../UPDATING.md).

## Fixed — backend image build fails: `FATAL: no SHA256 for oc-mirror.tar.gz`

- **What happened:** on 2026-11-19, building the backend image (Podman, Docker, compose, Tekton) began failing at the
  tool-download step with `FATAL: no SHA256 for oc-mirror.tar.gz`. The frontend image still built. Default backend
  builds of v2.2.1 and of development branches fail the same way until they carry this fix.
- **Why:** the image downloaded `oc-mirror` from Red Hat's global channel `clients/ocp/latest`. That channel now points
  to OpenShift 5.0.1, and the 5.0.1 checksum list publishes **no oc-mirror artifact** (neither `oc-mirror.tar.gz` nor
  `oc-mirror.rhel9.tar.gz`) on any architecture. The build failed closed, as designed, rather than install an
  unverified binary.
- **Fixed:** `oc-mirror` now comes from the newest patch of the newest supported minor, `clients/ocp/latest-4.22`
  (4.22.22 at release time), which still publishes `oc-mirror` with its checksum. This applies to the image, to the
  oc-mirror the app downloads for bundles, and, per guide minor, to the Field Guide's download command, whose
  `…/latest/oc-mirror.tar.gz` URL had become a 404.
- **Verification is stricter, not looser:**
  - the version is bound to the same checksum list as the tarball;
  - a missing checksum names the cause;
  - only the expected regular file is extracted;
  - its architecture is checked;
  - the binaries must run as the application user (UID 1001) during the build.

  TLS verification is unchanged. See [`docs/BUILD_TROUBLESHOOTING.md`](../BUILD_TROUBLESHOOTING.md).
- **Not changed:** OpenShift 5.0 is not supported. `oc` still follows the selected target minor.

## Security update in the frontend image

The frontend image now installs `krb5-libs` `1.21.1-10.el9_9.2` from the UBI 9 repositories. The current
`ubi9/nginx-124` base image still ships `1.21.1-10.el9_8.1`, which has 14 HIGH CVEs. Nothing else is upgraded.

## Kubernetes and OpenShift deployment

- **README fixed.** The production quick start applied the base manifests on OpenShift too. On OpenShift, use
  `oc apply -k manifests/openshift/`. It adds oauth-proxy login and pins no UID or fsGroup, so `restricted-v2` assigns
  both.
- **Clearer startup messages** for two misconfigurations of hand-written Deployments. Both behave as in v2.2.1:
  - **loopback bind:** a backend bound to loopback in a pod now logs a warning instead of only failing its readiness
    probe;
  - **unwritable volume:** `DATA_DIR … is not writable` now says when the volume belongs to a group (fsGroup) the pod
    does not carry.

  See [Troubleshooting in-cluster startup](../../manifests/README.md#troubleshooting-in-cluster-startup).

## Release gates

- **CI** now builds the backend image on every push to `main` and `develop` and checks the tools as UID 1001. Before,
  CI built only the frontend image.
- **CI** also builds and starts the frontend image with Podman/Buildah, and runs the backend startup-identity matrix,
  including volume permissions for the pod's group (fsGroup). The fsGroup is emulated with Podman.
- **Every release** must pass both the non-containerized local build and the local Podman build of both images. The
  closeout verifier refuses a release without that evidence ([`docs/CONTRIBUTING.md`](../CONTRIBUTING.md)).

## Not in this release

- Optional tool tarballs in transfers, and the v2.3.0 Upgrade workflow: unchanged plans, not included.
- **Node.js runtime advisory (F21)** in the Red Hat base image and the findings in the vendor `oc` / `oc-mirror`
  binaries: still open, as in v2.2.1.

## Certification

This file does not state a certification result for 2.2.2. Any verdict belongs to a run bound to the exact released
commit and is published with that release's evidence. Earlier verdicts and owner risk acceptances do **not** carry
over.

## Known limitations

As in v2.2.1:

- customer RHEL 9 / Podman 4.9.4 / FIPS hosts have not been verified;
- mirroring a real OpenShift release payload end to end has not been verified.

New in this list:

- **No real cluster deployment.** No release has been deployed to a real Kubernetes or OpenShift cluster. The
  manifests are checked statically, and the image's startup identities only under Podman emulation.
- **The base manifests on plain Kubernetes** may refuse to start on a container runtime that creates no
  `/run/.containerenv` or `/.dockerenv` marker file, such as containerd with cgroup v2. Not verified. The OpenShift
  overlay does not depend on these markers.

Architect makes no FIPS claim for `oc-mirror`.
