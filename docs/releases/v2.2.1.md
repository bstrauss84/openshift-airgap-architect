# OpenShift Airgap Architect v2.2.1

**Version:** 2.2.1 (PATCH) · **Supported OpenShift targets:** 4.20, 4.21, 4.22 (unchanged) ·
**Published assets, if any:** the [Releases page](https://github.com/bstrauss84/openshift-airgap-architect/releases)

v2.2.1 is a corrective release on top of [v2.2.0](v2.2.0.md). It fixes the v2.2.0 known issue: Mirroring runs fail
in the backend container. It also adds a release gate that would have caught that problem, and makes release tooling
corrections. It changes no OpenShift support, no dependencies or base images, and no deployment model. Build and run it
the usual way:

```bash
podman compose up --build -d
# or
docker compose up --build -d
```

Before updating, save your configuration with **Tools → Export Run**. Follow [`docs/UPDATING.md`](../UPDATING.md).
Rebuild the images: the correction is in the backend image, not in your data.

## Fixed — Mirroring runs fail in the v2.2.0 backend container

- **What happened:** in the v2.2.0 container every Mirroring run (mirror to disk, mirror to mirror, disk to mirror)
  stopped before `oc-mirror` started, with
  `The execution plan could not be written, so nothing was run: EACCES: permission denied, open '/usr/local/bin/oc-mirror'`.
- **Why:** the image kept the owner from Red Hat's tarball (uid 984) and only added the execute bit, so `oc-mirror` was
  mode `0751`. The backend runs as the non-root user `appuser` (uid 1001). It could execute `oc-mirror` but not read it,
  and Architect reads the binary to record its SHA-256 in every run plan.
- **Why testing missed it:** the v2.2.0 lab tests ran the backend on the host with a configured `oc-mirror`, not the
  container's own binary and user.
- **Fixed:** the image installs `oc` and `oc-mirror` owned by root with mode `0755`. The download, the check against Red
  Hat's checksum list and the binaries themselves are unchanged (`oc-mirror` 4.22.19 is still SHA-256 `55b55cf1…`).
- **Not affected in v2.2.0:** Install, operator catalog scans and the other workflows.

## New release gate

Certification now checks the final backend image as the application user, not as root:

- that user can read, hash and execute `oc-mirror` and `oc`;
- the backend's own code path resolves and hashes its `oc-mirror`.

These checks fail on the v2.2.0 image with `EACCES` and pass on the corrected image.

## Release tooling

- **Certification test isolation:** the backend unit tests no longer inherit the candidate image names that the image
  checks use.
- **Release closeout:** `scripts/release/verify-release-closeout.mjs` verifies a published release live and is the
  only way to record a release as closed. It checks:
  - the tag and its SSH signature;
  - that `main` and `develop` agree on every remote;
  - that CI passed;
  - that the release assets match `SHA256SUMS`.

  The documentation check refuses a "closed" claim without a passing record.
- **Backend tests on Node 22:** the backend test scripts now also run on Node 22 (the product runtime); before, they
  ran only on Node 20, which CI uses.

## Not in this release

- **Optional tool tarballs in transfers** (oc-mirror / oc next to a transfer): moved to a later release, pending a
  review of binary-level license notices.
- **Node.js runtime advisory (F21)** in the Red Hat base image: still open. There is no fixed Node.js 22 build, and
  moving to Node.js 24 needs a `better-sqlite3` major upgrade (a trial build failed). The findings in the vendor
  `oc` / `oc-mirror` binaries also remain.

## Certification

This file does not state a certification result for 2.2.1. Any verdict belongs to a run bound to the exact released
commit and is published with that release's evidence. The 2.2.0 verdict and owner risk acceptance do **not** carry
over.

## Known limitations

As in v2.2.0, these have not been verified:

- customer RHEL 9 / Podman 4.9.4 / FIPS hosts;
- mirroring a real OpenShift release payload end to end.

Architect makes no FIPS claim for `oc-mirror`.
