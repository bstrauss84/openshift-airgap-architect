# OpenShift Airgap Architect v2.1.2

**Version:** 2.1.2 (PATCH) · **Supported OpenShift targets:** 4.20, 4.21, 4.22 (unchanged) ·
**Published assets, if any:** the [Releases page](https://github.com/bstrauss84/openshift-airgap-architect/releases)

v2.1.2 is a maintenance release on top of [v2.1.1](v2.1.1.md). It fixes two ways in
which exported files could contain credentials the user had chosen to exclude, and
seven correctness and usability problems. It changes no OpenShift support, no
dependencies or base images, and no deployment model. Build and run it the usual way:

```bash
podman compose up --build -d
# or
docker compose up --build -d
```

Before updating, save your configuration with **Tools → Export Run**. Follow
[`docs/UPDATING.md`](../UPDATING.md).

## Security — read this first

Two export paths could write credentials into files even though Export Options said
they were excluded. They differ in how reachable they were.

### Per-file Download from the YAML preview (DOC-230, Medium) — user-accessible

- **What happened:** the **Download** button for a single file in the YAML preview
  drawer saved the preview content, and that content always carries credentials so that
  **Show sensitive values** can reveal them on screen. The downloaded file therefore
  included any of the following that were configured, **regardless of Export Options**:
  - the pull secret;
  - BMC, vCenter and Nutanix passwords;
  - proxy `user:password`;
  - the SSH public key.

  This happened even with every credential switch off and the values masked on screen.
- **Affected:** v2.1.0 and v2.1.1, through the normal UI.
- **Fixed:** a single-file download is now generated under the same Export Options as
  the bundle. It is byte-identical to that file in the bundle. If it cannot be
  generated that way, the download fails rather than falling back to the preview. Showing
  sensitive values changes only what is on screen. A note in the drawer says that
  downloads follow Export Options.

### Proxy credentials in the high-side runtime package (DOC-229, Low) — hidden path

- **What happened:** the run's export options could enable the high-side runtime package
  while the proxy URL contained `user:password`. In that case the credential was written
  in plaintext to `runtime-package/payloads/imported-run.bundle.json` inside the
  exported bundle, even with the credential switch off.
- **Affected:** v2.1.0 and v2.1.1. **The runtime-package switch is hidden in the
  v2.1.x UI**, so the only way to reach this was imported or API-supplied state that
  already had the option enabled.
- **Fixed:** proxy userinfo is removed from that payload unless credentials are
  explicitly included. The payload now also follows the **Proxy values** switch.

### What to do

Bundles and individually downloaded files produced by v2.1.0 or v2.1.1 in the
situations above may contain **real credentials**. If you produced or shared such
files, take these steps:

1. Securely delete every copy, including copies already carried to other systems or
   given to other people.
2. Rotate the affected credentials: pull secret, BMC/vCenter/Nutanix passwords, and
   proxy credentials.

## Fixed

1. **Export Options "Proxy values" and "SSH public key" take effect** (DOC-177).
   - Both switches previously did nothing.
   - With **Proxy values** off, each configured proxy value in the bundle's
     `install-config.yaml` and `FIELD_MANUAL.md` becomes a `REPLACE_WITH_…` marker. The
     proxy block is kept, and nothing is invented for unset values.
   - With **SSH public key** off, the optional `sshKey` is omitted.
   - Both switches default to on, so default bundles are unchanged.
2. **Imported host addresses in a disabled IP family are reported** (DOC-219).
   - Previously, an IPv4 address left on a host in an IPv6-only cluster (or the
     reverse) was silently dropped from the generated network configuration.
   - It now produces a non-blocking warning with **Remove unused IPv4/IPv6 values**.
     Importing still preserves the data.
   - The `rendezvousIP` in `agent-config.yaml` was always read from the IPv4 field. An
     IPv6-only cluster therefore got the leftover IPv4 address or a generic fallback.
     It now uses the address of the cluster's IP family.
3. **No fabricated "4.0" documentation links** (DOC-203).
   - Links to Red Hat documentation are shown only when a supported OpenShift version
     is selected.
   - The docs API now reports that a version is required, rejects an unselected version
     with 400 `VERSION_NOT_SELECTED`, and rejects an unsupported one with 422.
4. **VIP checks in the Field Guide** (DOC-148). The guide no longer tells you to ping a
   VIP and treat "0 received" as proof that it is free. A ping proves nothing about
   whether an address is reserved. The guide now asks you to confirm the reservation in
   your IP address management records, citing Red Hat's installation documentation.
   This applies to 4.20, 4.21 and 4.22.
5. **AWS GovCloud region dropdown stays single-line** (DOC-228). At some window widths,
   selecting a region made the dropdown about twice its normal height. This was a
   cosmetic issue, present since v2.1.0.
6. **Accurate post-import notice** (PHX-033, PHX-035).
   - After **Tools → Import Run**, a notice above every step lists only what this run
     must re-enter, each with its step. Examples are the mirror pull secret, vCenter
     credentials, proxy credentials, the mirror CA and the proxy CA.
   - Items clear as they are re-entered.
   - This replaces a note shown only on Blueprint that wrongly said the SSH key and
     certificates had been dropped.
   - Every configured vCenter now requires credentials.
7. **Clear message when installer extraction runs out of space.**
   - Problem: the AWS AMI lookup extracts `openshift-install`, roughly 750 MB. If disk
     space or a quota ran out during extraction, the app showed raw `tar` output (for
     example "Wrote only 2048 of 10240 bytes").
   - Fix: the message now names the cause, the version and the directory, and says that
     the verified download is kept for a retry.

### For developers

- End-to-end tests now refuse to start unless an isolated environment is explicitly
  selected. They also refuse ports 4000/5173 unless those are declared disposable.
  Previously, a plain `npm run test:e2e` targeted, and reset, a locally running
  instance.
- Regression tests protect cloud availability-zone entry (DOC-115). The original
  defect is not reproducible in current code, and there is no production change.

## Testing and certification

- **What was run on this source:**
  - the full frontend, backend and tooling suites;
  - the version, catalog, documentation and secret-scanning gates;
  - the production build;
  - real-browser checks of the changed screens against an isolated instance.
- **Owner acceptance:** the maintainer walked through six representative checks on an
  isolated build, and all passed:
  1. the post-import notice;
  2. the IPv6-only leftover-IPv4 warning;
  3. the Proxy values switch;
  4. the per-file Download policy;
  5. the GovCloud region dropdown and AMI lookup;
  6. the Field Guide VIP guidance.

  This is acceptance of those behaviours. It is not verification of untested
  environments.
- **Not exercised manually:**
  - the runtime-package fix (automated tests only, because its switch is hidden);
  - the "select an OpenShift version" docs message;
  - exact-binary `openshift-install agent create image` validation of an IPv6
    `rendezvousIP`.
- **Certification.** This document deliberately states **no** certification verdict for
  v2.1.2. A verdict is valid only for a run bound to the exact released commit. It is
  published with that release's evidence on the
  [Releases page](https://github.com/bstrauss84/openshift-airgap-architect/releases),
  together with any owner risk acceptance. The v2.1.1 certification evidence, verdict
  and owner acceptance are bound to the v2.1.1 commit and **do not carry over**.
- **Earlier findings still apply.** This patch changes no base images or dependencies.
  The image-vulnerability findings reported for v2.1.0 and v2.1.1 are therefore **not**
  resolved by it. See [SBOM and provenance](../security/SBOM_AND_PROVENANCE.md).
